# Frontend infrastructure — deviations to merge into DECISIONS.md

| # | Topic | Prototype / sources | What the MVP does | Why |
|---|---|---|---|---|
| F1 | Routing | State-based routing in `App.tsx`, every page gets `onNavigate(route)` | React Router v6 (`BrowserRouter`) with real URLs. Pages keep the `onNavigate(route, reportId?)` prop through a shim (`useAppNavigate` in `App.tsx`) that calls `navigate()`; `onNavigate('/reports', id)` goes to `/reports/:id` | Shareable links without rewriting every page now |
| F2 | URLs | `/scenario`, `/simulation`, … only | Same paths kept, plus `/simulation/runs/:runId` (run results), `/reports/:reportId`, `/about`, `/admin/*`. Comparison and geographic state go in the query string (`/scenario?runs=a,b,c&capacity=x`, `/geographic?run=…&capacity=…`) | Docs Module 12 asks for run ids in the page address |
| F3 | Route guard | No guard; nav hides links by role | Signed-out users go to `/login` (the attempted URL is carried through login and MFA and reopened afterwards). Roles without access per `hasAccess(role, ROUTE_MODULES[path])` see a "not available to your role" message. `/healthcare` keeps its per-role page choice. Admin is confined to `/admin/*`; other roles are sent away from it | Mirrors `src/lib/rbac.ts`; the server enforces the same matrix |
| F4 | Role switcher | Top-bar switcher changed the role in memory | In DEMO_MODE it calls `POST /api/auth/demo-login {role}` and swaps the token (query cache cleared). Outside DEMO_MODE the role chip is shown but not clickable | Every role change is a real server session, so RBAC is exercised |
| F5 | Token storage | n/a | JWT in `localStorage` (`episim.token`), wrapped in try/catch; a 401 from any call clears it and returns to `/login` | Acceptable for a demo; production should use httpOnly cookies |
| F6 | Login | Hard-coded demo users checked in the browser | `POST /api/auth/login`. The demo quick-fill list is unchanged (same emails and passwords), so **the backend seed must use those credentials**: admin@moh.gov.rw/admin123, epidemiologist@rbc.gov.rw/epi123, officer@who.int/officer123, policymaker@moh.gov.rw/policy123. Accounts approved in-browser via the (still local) access-request flow sign in as the demo user of their assigned role | Keep the prototype's demo script; the access-request flow is wired to the API in a later phase |
| F7 | MFA | Mock screen | Still a mock, now labelled "Mock step in this demo: no code is sent or checked" | Honesty rules |
| F8 | Header status | "System Online · v2.4.1-stable" (static) | Online/offline from `GET /api/meta`, showing app and engine versions | Avoid a fake status |
| F9 | `useScreenInit` / `canvas.manifest.js` | Design-tool preview state | Manifest removed; `useScreenInit()` returns a frozen `{}` until the remaining calls are removed | Not part of the real app |
| F10 | React entry | `ReactDOM.render` (legacy) | `createRoot`, no StrictMode (the prototype contexts run timers in effects and were not written for double-invoked effects) | React 18 API |
| F11 | Built-in preset editing | `canEditBuiltIns` App prop | Constant `false` in the UI; the server decides | No elevated permission for demo users |
