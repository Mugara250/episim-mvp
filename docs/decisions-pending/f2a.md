# F2a — configuration data pages (population, presets, interventions, capacity)

| Topic | Sources say | What we did | Why |
|---|---|---|---|
| Import row checks | Prototype checked rows in the browser (first rows only for big files, with canned counts for the sample) | Every row is checked by `POST /api/population/imports/check`; the browser only reads the header and a preview. Client-side check functions were removed | One set of rules (server), so the screen and the import always agree; no canned numbers |
| Import size limit | Prototype UI: 2 GB, background over 50 MB | UI says 50 MB (the MVP backend limit); every import is a background job polled every 0.7 s | Matches what the backend accepts |
| Demo sample file | Prototype simulated "RPHC5 2022 10% sample" with fixed counts | `frontend/public/samples/episim_illustrative_district_counts.csv`: district totals approximating the 2022 census split into invented age bands, with two deliberately invalid rows; labelled Illustrative and run through the real check/import | The demo import is real end to end without pretending to be census microdata |
| Imported sample dataset flag | — | A dataset created from the sample is not flagged `illustrative` by the backend (only seeded rows are) | Backend sets the flag on seed only; noted as a gap |
| "Compute aggregates" step | Prototype: separate step after a microdata import | Removed the button; district totals are computed by the server during the import and the panel says so | The backend already aggregates to districts in the import job |
| Same-name import | Prototype: same name → new version | The wizard matches the name against `/api/population/datasets` and sends `datasetId`, so the server adds a version | Backend creates a new dataset when no `datasetId` is sent |
| Region reference lists | `src/data/populationImport.ts` | NISR province/district lists, sector names for 4 districts, field specs and sources moved to `utils/populationImport.ts`; data file deleted | They are reference/UI constants, not mock records. Sector numbering is alphabetical and unverified against NISR |
| Disease preset fields | Prototype page: generic R0, incubation, infectious days, mortality, asymptomatic, route | Page shows and edits the SEIHFR fields (docs Module 4/D15) in groups, plus run defaults (initial cases, HCW protection, recognition day). Legacy `DiseasePreset` type kept as `@deprecated` for unconverted screens | D15 |
| Preset approval | Docs: approve endpoint for epidemiologists | "Approve values" and "Approve and clear Provisional" buttons (analyst only). Editing a preset bumps its version and clears approval (server) | Provisional is cleared only by an explicit act |
| Built-in presets | Prototype: "validated reference values" | Copy changed to "read-only so scenarios stay stable"; no validation claim | Honesty rules: no claims of validation |
| Intervention model lever | Prototype had no lever field | Lever shown in the type table and editable in the type panel; shift ↔ vaccination enforced in the UI as on the server | Docs Module 8 engine_lever |
| Screen-init demo states | Prototype `useScreenInit` states (empty package, item editor open, no custom types, seeded import status) | Removed; screens open the first record from the API | Design-preview states are not real data |
| Capacity gap preview | Prototype compared the draft with a fixed "example peak" from `data/capacityProfiles.ts` | Kept the fixed example inside `GapPreview.tsx`, labelled "Illustrative example, not a simulation result" | Real capacity checks live on run results / comparison / geographic pages |
| Capacity per-district beds | Not edited on this page | Saving a profile resends its existing `districtBeds` so they are not wiped | `PUT` replaces the whole profile |
| Capacity access | rbac.ts: analyst `capacity: none` | Page unchanged (route guard hides it); other screens should use `useCapacityOptions()` from `src/api/capacity.ts` | Backend `/capacity-profiles/options` serves analysis-time selectors |
