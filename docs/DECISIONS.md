# Decisions, conflicts and deviations

Precedence when sources disagree: (1) the MVP build prompt, (2) the frontend prototype's
behaviour and `src/lib/rbac.ts`, (3) `epidemic-simulation-full-documentation.md`.
Each entry says what the sources said, what we did, and why. Entries marked **needs review**
should be looked at by an epidemiologist or the product owner.

## Simulation engine

| Topic | Sources say | What we did | Why |
|---|---|---|---|
| Random numbers | TS engine: mulberry32 RNG; binomial draws use Poisson (mean < 10) or rounded-normal approximations for n ≥ 40 | NumPy `Generator(PCG64(seed))` with exact binomial, Poisson and gamma draws | Vectorised over runs and statistically exact. The same seed gives identical output in Python. It does not reproduce the TS numbers, so parity is distribution-level (`test_parity.py`: probabilities within 0.07, medians and 95th percentiles within 25% + 5). Python Ebola medians come out about 10–15% above the TS ones, which is within seed noise for heavy-tailed outbreak sizes |
| One core for both models | Prompt: dispatch by model type | `core.simulate` is a metapopulation simulator; `seihfr` runs it with one district and no movement, which is algebraically the TS model | One set of equations to review and test |
| Lever mapping | Docs Module 8 lever table; prototype `utils/seihfr.ts` effects | contact_tracing → contact tracing; case_isolation → isolation (hospital route only, as in docs); safe_burials → safe burial; testing → detection delay × (1 − coverage·effect), floor 1 day; lockdown → community multiplier; masking → community and hospital multipliers; vaccination (shift) → daily S→R chance = coverage·effect ÷ window length (same as `utils/seihfr.ts`). A custom type with no known lever acts on the community multiplier if it is a rate type, and on vaccination if it is a shift type | The docs leave masking, lockdown and vaccination "to add". The prototype's deterministic engine also had case isolation cut community spread; we follow the docs. **Needs review** |
| Combination rule (D14) | Docs: `baseline + (1 − baseline) × coverage × effect`; several items combine multiplicatively on the remaining gap | Implemented as written: `1 − (1 − baseline) × Π(1 − coverage·effect)`. The multiplier levers (community, hospital, detection) use `Π(1 − coverage·effect)` | Docs rule. Proposed, **needs review** |
| Time windows | Docs: day-by-day lever values | An item is active for `start_day ≤ day ≤ end_day` (`end_day` null means it runs to the horizon); transitions on day d use lever[d] | Inclusive end, as in `utils/seihfr.ts` |
| Route shares and baseline levers | Docs D13: move them onto the preset | Read from `snapshot.disease.route_share` and `.baseline`; when absent they default to 0.55/0.15/0.30 and 0.5/0.4/0.5 | D13 (proposed) |
| Recovered count | Prototype's run tiles show "recovered" from the deterministic engine | `summary.recovered` = people who recovered (community and hospital) per run, as 5/50/95 percentiles. Safe burials are not counted | Matches the tile's meaning |
| Peak tiles | Prototype tiles: peak infectious and peak day | `summary.peak_infectious` and `peak_day` are per-run percentiles of the active (I+H) peak and the day it occurs. `summary.median_curve_peak` is the peak of the median curve | Both are useful. The per-run median peak day is often late because many runs are still growing at the horizon |
| Movement model | Docs Module 9: gravity model, labelled "estimated" | trips ∝ PᵢPⱼ ÷ (d² + 10²) with d the haversine km between centroids. Each district's residents spend **2%** of their time in other districts (`away_share`, configurable in `geo.movement`). Only community-infectious people (I) mix; H and F transmit locally to whoever is present. Residents' exposure = Σⱼ M[i,j] · force in j | No mobility data exists. 2% is an invented assumption (about 30 minutes a day away from home on average). Spread timing is very sensitive to it: with Ebola defaults, the outbreak usually stays in the seed district at 1–2% and reaches neighbours at 4–5%. **Largest uncertainty; needs review**; always labelled estimated |
| Branching phase in the geo model | TS: negative binomial while the run total < 20 cases | Applied per district: while a district's cumulative cases < `branching_until`, its new infections are negative-binomial with k × max(1, local I+H+F) | A natural extension. Imported pressure into a district with no local cases uses k × 1 |
| Health-worker pool in the geo model | Docs: a single staff pool for the area | The national pool (default 600) is split across districts in proportion to population (rounded) | Each district's hospitals infect their own staff |
| What-if "full response" | Docs: response levers active from day X in district Y | From `start_day` the district's levers become at least contact tracing 0.8, isolation 0.9 and safe burial 0.9, and detection delay is halved (floor 1 day). Values are never weakened below the package | Placeholder values, **needs review** |
| Border importation | Docs: risk is a configurable assumption, not a calculation | `geo.border_importation` optional list of `{country, risk, entry_district_code, weekly_rate}` adds Poisson(weekly_rate ÷ 7) imported infections a day in the entry district. **Off by default** | Keeps chips honest: risk labels are shown, not modelled, unless someone sets a rate |
| District first-case day | Docs: distribution, median shown | Runs that never reach a district count as "day horizon + 1". The 5/50/95 percentiles are taken over all runs, and a percentile beyond the horizon is reported as `null` | Gives "not reached in most runs" an honest `null` median. `p_reached` is reported too |
| Series storage | Docs: summaries in columns, series stored apart | The result holds columnar bands rounded to 2 decimals (~26 KB national, ~250 KB geo for 30 districts × 181 days) | Small enough for a JSON column |
| Reference engine | Prompt: move the TS engine to tools/reference-engine and remove it from the bundle | Moved: the TS engine lives only in `tools/reference-engine/` (imports edited for Node type stripping); `frontend/src/lib/models` was deleted once no page used it | Reference outputs for the parity test; nothing in the app bundle runs it |
